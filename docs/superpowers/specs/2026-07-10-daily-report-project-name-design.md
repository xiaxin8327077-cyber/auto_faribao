# 日报正文增加智能文档项目名称设计

## 目标

从企业微信智能表格的“所属项目”关联字段读取真实项目名称，并在智能文档生成的每条日报任务前显示：

```text
1. 【数据管理平台实施工作】任务名称：任务描述
2. 【日常工作：数据中台优化】任务名称：任务描述
```

## 数据来源

- 子任务表：`项目子任务管理`
- 子任务项目字段：`所属项目`，关联字段类型 21
- 关联项目表：`项目管理`
- 关联项目主字段：`项目名称`

提取任务前一次性预加载关联项目表，再从“所属项目”的标准单元格数据中读取显示文本。不得使用关联记录 ID、OA 默认项目名称或人工映射代替真实项目名称。

## 数据处理

智能表格脚本返回结构化任务数据：项目名称、任务名称、任务描述。Python 层将每条数据格式化为最终字符串，并保持 `extract_tasks()` 的现有 `list[str]` 返回接口不变，避免影响日报构建和其他调用方。

格式规则：

- 有项目名称：`【项目名称】任务名称：任务描述`
- 无任务描述：`【项目名称】任务名称`
- 项目为空、无读取权限、关联数据尚未加载或显示为占位符 `...`：保留原格式 `任务名称：任务描述`
- 项目解析失败不得阻断整份日报生成

## 影响范围

- “发送日报”和定时日报：提交正文增加项目名称
- “读取日报”：预览内容同步增加项目名称
- 智能文档失败后的历史 OA 日报兜底：保持历史原文，不二次加工
- OA 表单中的默认项目选择：保持现状
- 手工提交日报、指定日期日报查询、净值相关功能：不变

## 配置

`SourceConfig` 增加 `project_field`，默认值为 `所属项目`。当前服务器配置无需修改；如智能表格将来改列名，可通过 `config.yaml` 覆盖。

## 错误处理

关联表预加载或项目字段解析失败时记录警告，并继续使用不含项目名称的原任务文本。任务名称、负责人和任务状态等现有必需字段校验保持不变。

## 测试

- 配置默认项目字段名称为“所属项目”
- 有项目、有描述时生成完整格式
- 有项目、无描述时不附加冒号
- 项目为空或为 `...` 时保持旧格式
- `extract_tasks()` 返回类型不变
- 日报构建、Cookie 续期和历史日报兜底现有回归测试全部通过
