# 全局 AGENTS 质量护栏设计

## 目标

为所有项目提供一套语言无关、模型无关的开发规则，减少“只修已指出的一处、遗漏相邻入口、测试全绿但真实路径未覆盖”的返工。

规则采用平衡型强制流程：复杂修改必须完成全链路分析和真实验证；简单改字、注释及纯格式调整允许使用轻量流程，避免不必要的 Token 消耗。

## 使用方式

最终交付是一段可直接追加到全局 `AGENTS.md` 的独立 Markdown 章节，不覆盖用户已有的 Shell、Git 或项目偏好。

规则作用于：

- 功能开发、Bug 修复、重构、配置行为变更。
- 后端、前端、脚本、桌面端、移动端及基础设施项目。
- 任意编程语言和测试框架。

## 工作分级

### 轻量任务

仅限不会改变运行时行为的改字、注释、排版和机械格式调整。

要求：

- 检查差异范围。
- 运行与改动直接相关的最低成本检查。
- 不得借轻量任务扩大代码修改范围。

### 行为任务

凡是改变功能、状态、数据、错误处理、并发、配置或外部交互的修改，必须执行完整流程。

## 完整流程

### 1. 修改前分析

编码前必须列出：

- 用户可见的目标行为和明确非目标。
- 所有调用入口、调用方、后台任务、命令行入口和回调。
- 正常、失败、超时、重试、同值重试、重复回调、并发及进程重启状态。
- 磁盘、数据库、缓存和进程内状态之间的同步关系。
- 成功、失败和不确定状态下的用户通知。

不能只搜索用户提到的函数；必须搜索相关函数、异常和状态的全部引用。

### 2. 测试先行

Bug 修复必须先建立能复现原问题的失败测试。功能开发必须先确定验收测试。

有效测试必须：

- 调用真实生产入口或可复用的生产辅助函数。
- 证明修复前失败、修复后通过。
- 覆盖主路径及关键反例。
- 隔离本机配置、凭据、时间、网络和工作目录。

明确禁止：

- 在测试中复制生产分支后测试复制品。
- Mock 掉被验证的核心行为，再用 Mock 返回值证明正确。
- 依赖开发机真实配置、Cookie、数据库或固定工作目录。
- 仅断言“函数被调用”，却不验证最终状态或用户结果。

### 3. 实现约束

- 优先修复根因，并让所有入口复用同一行为。
- 新异常子类加入后，检查所有父类捕获位置及捕获顺序。
- 持锁、事务、资源关闭和回调必须有明确所有权。
- 不得把“未知或未验证”冒充成功或确定失败。
- 不得记录密钥、Cookie、令牌、密码或完整凭据。
- 不得用重启掩盖可在运行时正确同步的问题。

### 4. 完成前验证

至少执行：

- 针对原问题的专项测试。
- 受影响模块的完整测试。
- 项目完整测试集。
- 编译、类型、Lint 或等价静态检查。
- 差异检查，确认没有凭据、生产数据和无关文件。
- 从不同工作目录或干净临时环境运行关键测试。

高风险状态流还必须进行反例验证，例如：

- 首次失败后再次提交相同内容。
- 更新成功但通知、刷新或清理失败。
- 任务执行期间发生并发命令或重复回调。
- 写盘后、同步前发生进程重启。
- 资源关闭自身抛出异常。

### 5. 完成报告

不得仅凭“测试全绿”宣称完成。最终报告必须写明：

- 修改覆盖了哪些入口和状态。
- 实际运行的命令、测试数量及结果。
- 是否执行隔离环境验证。
- 尚未覆盖的路径、假设和残余风险。
- 是否修改、提交、推送或部署。

发现 Important 或 Critical 问题时不得报告“全部完成”。

## Token 控制

- 先做一次调用方和状态矩阵，避免多轮补丁。
- 同类入口并行检查，测试集中运行。
- 只对行为任务使用完整流程。
- 已有可靠测试可复用，但不得用数量代替覆盖质量。
- 信息不足但可通过只读检查发现时，先检查再询问用户。

## 验收标准

- 规则可直接追加到现有全局 `AGENTS.md`，不依赖特定项目或语言。
- 明确区分轻量任务和行为任务。
- 普通执行模型能够据此自行发现相邻入口和状态边界。
- 明确禁止假回归测试和本机环境依赖。
- 强制提供可核验的完成证据和残余风险。
- 文本足够具体可执行，同时避免要求所有任务都走重流程。
