# 理财定投新增每周与每月周期设计

## 背景与目标

当前理财组合的定投计划仅支持按交易日每日执行。本次扩展在保留每日定投和现有历史数据行为的基础上，新增每周、每月定投，并允许用户为每个计划单选一个扣款日。

## 功能范围

- 定投周期支持每日、每周、每月。
- 每周定投可单选周一至周五。
- 每月定投可单选 1 至 31 日。
- 开始日期只控制计划何时生效，不隐式决定每周或每月的扣款日。
- 计划扣款日不是交易日时，顺延到下一个交易日。
- 每月选择 29、30 或 31 日，而当月没有该日期时，以当月最后一个自然日作为计划扣款日，再按非交易日顺延规则处理。
- 每个计划只配置一个周期扣款日；需要一周或一月执行多次时，应创建多个计划。
- 原有定投计划迁移后均保持为每日定投。

## 不在范围内

- 每周或每月多选多个扣款日。
- 自定义 Cron 表达式或任意复杂周期。
- 非交易日提前扣款。
- 为新增周期追补功能上线前的历史执行。

## 数据模型与兼容

`sip_plans` 新增两个字段：

- `frequency`：`daily`、`weekly` 或 `monthly`，非空，旧数据默认 `daily`。
- `schedule_day`：每日定投为空；每周使用 ISO 星期数 1 至 5；每月使用日期 1 至 31。

领域模型 `SipPlan` 同步增加上述字段。数据库迁移必须为已有数据库补列，并确保旧计划读取为每日定投。仓储层负责完整保存和读取周期字段。

## 执行规则

周期计算以北京时间的自然日和现有交易日历为准：

- 每日：沿用当前行为，在每个交易日执行。
- 每周：找到开始日期当日或之后、星期数与 `schedule_day` 相同的计划日。
- 每月：取每月的 `schedule_day`；若该月没有该日，则取当月最后一日。
- 周期计划日若不是交易日，逐日向后查找下一个交易日，并在该交易日执行。

开始日期是生效边界。开始日期之前的周期计划不生成交易；开始日期之后首次匹配的周期计划才进入执行。顺延后的真实执行日期用于行情确认、资金划扣和执行幂等，确保同一计划在同一交易日最多扣款一次。

暂停、恢复、余额不足、产品停用、行情确认、通知和交易冲正规则沿用现有实现。恢复计划不追补暂停期间错过的周期。

当交易日历缺失、无法确定顺延结果时不得扣款，并沿用现有日历不可用处理，待交易日历恢复后由现有补跑机制重新判断。

## API

定投预览与写入接口新增：

- `frequency`
- `schedule_day`

服务端校验：

- `daily` 要求 `schedule_day` 为空。
- `weekly` 要求 `schedule_day` 为 1 至 5 的整数。
- `monthly` 要求 `schedule_day` 为 1 至 31 的整数。
- 缺失 `frequency` 时按 `daily` 处理，以兼容旧客户端。

预览响应和理财看板数据均返回标准化后的周期字段。

## 页面交互

定投新建和修改弹窗新增“定投周期”：

- 选择每日时不显示扣款日选择控件。
- 选择每周时显示周一至周五单选控件。
- 选择每月时显示 1 至 31 日单选控件。
- 修改已有计划时回填周期和扣款日。
- “首次扣款日”文案改为“开始日期”。

定投卡片新增周期摘要，分别显示“每日”“每周一”至“每周五”或“每月 N 日”。确认预览使用中文字段名展示周期及扣款日。

## 错误与边界处理

- 非法周期或不匹配的扣款日由服务端拒绝，页面展示接口返回的校验错误。
- 每月月底顺延可能进入下一个自然月，但仍只代表原月份的那一次计划。
- 如果两个不同月份的计划经长假顺延到同一交易日，计划级交易日幂等保证只扣款一次，避免同一计划同日重复划扣。
- 现有每日计划的接口请求、数据库数据和页面展示保持兼容。

## 测试与验收

- 数据库迁移测试：旧计划自动成为每日计划，新字段可持久化。
- 领域校验测试：每日、每周、每月合法值通过，非法组合被拒绝。
- 执行测试：每周命中工作日、每周节假日顺延、每月命中日期、月底缺日、周末或节假日顺延。
- 生命周期测试：暂停和恢复不追补错过周期，幂等行为保持不变。
- API 测试：预览、创建、修改和读取完整往返周期字段。
- 页面测试：周期控件、条件显示、编辑回填、卡片摘要和预览标签存在。
- 回归测试：现有定投、交易、持仓、API 和理财看板测试通过。

验收标准是用户可以在理财看板中创建或修改每日、每周或每月定投；每周仅能选择周一至周五；每月可选择 1 至 31 日；非交易日按规则顺延；旧计划行为不变。
