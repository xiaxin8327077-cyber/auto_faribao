# 指定日期日报查询设计

## 目标

通过企业微信查询任意指定日期的 OA 日报，成功时只回复日报正文，不附带状态、项目或其他元数据。

## 指令识别

支持以下等价表达：

- `查询日报 20260709`
- `查询日报 2026-07-09`
- `查询2026-07-08日报`
- `查20260708日报`
- `帮我看 7月9日的日报`
- `查昨天日报`
- `看前天日报`

解析规则：

- `YYYYMMDD` 和 `YYYY-MM-DD` 可位于“日报”前或后，且不要求空格。
- `M月D日` 使用当前北京时间的年份。
- `今天`、`昨天`、`前天` 使用当前北京时间计算。
- 仅当文本同时包含“日报”和查询意图（查询、查、看、查看、读取）时进入该功能，避免干扰发送、撤回和统计指令。

## 查询流程

1. 服务端把自然语言归一为内部指令 `查询日报 YYYY-MM-DD`。
2. OA 登录后从当前页开始逐页扫描历史日报，按日期精确匹配；最多沿用现有 12 页安全上限。
3. 找到匹配行后，依次尝试展开详情、列表正文、查看详情窗口三种既有读取方式。
4. 企业微信只发送读取出的正文。

## 异常反馈

- 日期不能解析：`❌ 未识别到有效日期，例如：查询日报 20260709`。
- OA 中没有该日期记录：`ℹ️ 未找到 2026-07-09 的日报正文`。
- 找到记录但正文读取失败：`❌ 未能读取 2026-07-09 的日报正文`。
- 查询异常：保留现有 `❌ 查询失败` 格式。

## 方案选择

采用跨分页精确查询。仅复用首页查询会遗漏较早日报；用“上一份日报”反查无法保证日期精确。

## 测试边界

1. 日期和自然语言归一化，包括数字日期、带连字符日期、月日、今天、昨天、前天。
2. 非查询类日报指令不被误识别。
3. OA 精确日期查询在第一页和后续页均可找到目标行。
4. 结果仅返回正文；无记录和无正文分别返回对应提示。
5. 现有日报提交、前一天日报、净值指令回归通过。
