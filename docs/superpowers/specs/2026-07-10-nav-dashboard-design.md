# 理财组合看板设计

## 目标

在现有 `auto_faribao` 服务中增加公开访问的手机版理财组合看板，展示当前持仓、最新净值、收益流水、组合累计收益及贡献排行。页面地址为 `/nav`，不设置登录认证。

网页功能不得改变企微 08:08 日报、23:30 晚报、周期报告或企微手动查询的净值口径和发送行为。

## 页面

沿用已确认的 `docs/nav-dashboard-mobile-preview.html` 视觉方向，实际页面使用 HTML/CSS 响应式渲染，最大内容宽度 430px，在手机和桌面浏览器中保持清晰。

页面包含：

- 累计收益、今日收益、统计起点及正负收益天气状态
- 估算市值、已设置份额数量、今日披露数量
- 今日主要拖累和最大贡献
- 当前产品持仓列表：名称、代码、最新净值、日期、最近一期收益和涨跌幅
- 收益贡献与拖累排行
- 数据更新时间、刷新状态和手动刷新按钮

上涨及正收益使用橙红色，下跌及负收益使用绿色，延续现有企微净值图片规则。

## 路由

- `GET /nav`：返回看板页面
- `GET /api/nav-dashboard`：只读取本地状态并返回 JSON，不访问理财官网
- `POST /api/nav-dashboard/refresh`：请求异步手动刷新

手动刷新全局冷却 5 分钟。刷新已在执行、企微查询正在执行或冷却未结束时，不重复访问官网，返回当前状态供页面展示。

## 查询协调

企微查询优先，并保持直连官网：

1. 企微最新净值查询仍直接调用现有产品提供方，不使用网页缓存。
2. 企微查询成功后，将同一批 `ProductNavResult` 旁路写入网页状态，网页不再重复抓取。
3. 所有最新净值抓取共用单实例查询锁，避免网页、企微和手动刷新并发请求官网。
4. 网页后台仅在最后一次成功官网查询超过一小时时补充抓取。
5. 距离下一次企微 08:08 或 23:30 定时查询不足一小时时，网页自动抓取延后，等待企微结果。
6. 网页手动刷新若遇到企微查询执行中，返回“等待企微查询结果”，不排队追加一次请求。
7. 网页抓取失败只保留旧缓存和错误状态，不发送企微消息。

周期统计继续使用现有历史查询逻辑。网页调度不会在企微定时任务附近额外调用官网。

## 收益流水

新增独立状态文件，默认路径 `data/nav_dashboard_state.json`，采用临时文件加 `os.replace()` 原子写入，并使用进程内可重入锁保护。

状态包含：

- 版本号和统计起点 `2026-07-01`
- 产品生命周期及当前有效份额
- 产品增加、删除和份额变化事件
- 已处理的净值节点
- 按产品和净值日期去重的收益流水
- 最新持仓快照、最后尝试时间、最后成功时间和错误信息

计算规则：

- 首次上线将当前配置产品及当前份额视为自 `2026-07-01` 生效。
- 初始回溯使用统计起点之前最近一期净值作为基准，计入净值日期为 `2026-07-01` 及之后的收益。
- 每条收益为 `本期单位净值差 × 当时有效份额`，写入后不因未来份额变化而修改。
- 份额变化仅作用于尚未出现的新净值节点。
- 新产品从确认添加后的基准净值开始，添加前历史收益不计入。
- 产品删除后停止产生新收益，但历史流水和组合累计收益保留。
- 未设置份额的产品展示净值，但不计算市值和收益。
- 重复抓取同一产品同一净值日期时不重复记账。

“今日收益”和“今日披露”按该净值收益首次被系统抓取的北京时间自然日统计。累计收益为所有历史流水之和，包括已删除产品。

## 产品配置同步

现有配置持久化成功后，旁路调用看板组合同步：

- 新代码记录产品新增事件
- 份额变化记录新份额事件
- 配置中消失的代码记录删除事件
- 仅修改推送开关或时间不会产生组合事件

看板同步异常只记录日志，不回滚配置、不改变企微指令回复。

## 调度

现有调度线程每 30 秒检查一次看板刷新条件，但只在满足“一小时过期、无查询执行、非企微定时前一小时”时启动后台刷新线程。服务启动后状态不存在时自动初始化；部署时另执行一次只读初始化验证。

## 模块边界

- `src/nav_dashboard.py`：状态、流水、聚合数据、刷新控制和 HTML 渲染
- `src/nav_monitor.py`：现有官网查询；增加查询来源与结果旁路观察，不改变报告格式
- `src/scheduler.py`：增加看板到期检查，不改现有企微任务判断
- `src/server.py`：增加三个公开路由，并在配置持久化后同步组合状态

## 错误与恢复

- 状态文件损坏时备份损坏文件并重新初始化，不影响企微查询。
- 单个产品查询失败时保留该产品上次快照，其他产品继续更新。
- 全部产品失败时不更新最后成功时间，页面展示上次成功数据及错误摘要。
- 服务重启后从状态文件恢复收益流水和刷新冷却。
- 手动刷新接口始终快速返回，官网访问在后台线程执行。

## 测试与验收

- 初始回溯、份额变化、新增、删除和收益去重单元测试
- 企微结果旁路写入但企微仍直连的回归测试
- 自动刷新一小时判断、企微定时前一小时延后、5 分钟手动冷却测试
- API 只读与异步刷新测试
- 完整现有测试集
- 使用生产配置进行只读初始化，核对累计收益及五个产品
- 使用浏览器在 390px 和 430px 视口截图，检查无溢出、无重叠、字体和图标清晰
- 生产服务启动、哈希、日志和现有调度配置检查
