# 理财资金链路验收约束

适用范围：总资产、钱包可用/待确认资金、申购、赎回到账、确认、每日收益、人工校准，以及会改变这些结果的排序、重试和冲正逻辑。

## 为什么单次对账还不够

2026-09-22 对修复前生产快照的只读检查确认：9 月 19、20、21 日的近零错误收益均通过了 `portfolio_reconciliation`，审计中的 `actual_delta` 等于 `expected_delta`。现有对账能拦截不平衡的资金腿、持仓与账本不一致等错误，但收益金额及其份额来源于同一套计算，错误收益也可以形成平衡账本。

因此，资金类变更须同时验证业务预期、持久化账本、投影和页面结果。不能仅凭测试数量、接口 HTTP 200 或账本平衡判断金额正确。

## 必须保持的业务约束

| 环节 | 独立验收条件 |
| --- | --- |
| 内部转账 | 固定净值且无费用时，来源扣款、目标持仓或在途合计保持总资产不变。费用、收益及人工校准的影响单独列明。 |
| 钱包待确认申购 | 已包含在钱包当前持仓的金额不能再次加进总资产；待确认可用余额必须扣除已分配给转出的部分。 |
| 实时转出 | 优先使用可用待确认资金，只有超过该余额的部分才减少已确认生息本金；页面在途余额和历史计息使用相同分配规则。 |
| 申购确认 | 在途转为已确认不产生新的外部资金；已经消费的待确认金额不能在确认日再次增加持仓或生息本金。 |
| 每日收益 | 独立列出前一自然日的已确认可生息本金和万份收益，验证金额；检查应计日期完整性，包含周末，并排除尚未到期的日期。 |
| 幂等与恢复 | 重复运行、重建服务对象后重跑，均不得新增已完成交易/收益或改变余额。不能只检查同一对象的内存去重。 |
| 取消、冲正 | 退款与原资金分配一致；反转链按有效流水判断，双重冲正恢复的原交易不能被忽略。 |
| 人工校准 | 原记录和目标保留；历史补账必须区分校准前后已入账金额，避免重复增加已校准资金。 |

## 完整链路验收示例

使用确定性行情和临时数据库，调用实际业务服务及组合周期；仅替换外部行情和时钟，不能替换持仓、资金分配、收益或页面汇总计算。

初始钱包已确认 10,000 元，来源基金 5,000 元，基金净值为 1，总资产 15,000 元。周五赎回来源基金并到账钱包，形成周一确认的 5,000 元申购。当天再从钱包转出 12,000 元申购另一基金：

- 钱包实际余额为 3,000 元，钱包该批待确认可用余额为零。
- 目标基金待确认 12,000 元，总资产仍为 15,000 元。
- 若从周六起万份收益为 0.5，周六、周日、周一收益依次为 `0.15`、`0.1500075`、`0.150015000375` 元。更早日期设为零收益，避免混入其他收益。
- 周一确认后，目标基金份额为 12,000；已经用掉的钱包 5,000 元不能重新出现。
- 三天收益记账后，钱包为 `3000.450022500375` 元，总资产为 `15000.450022500375` 元。

上述金额来自独立算术预期，不从被测投影反推。每个业务阶段都检查真实页面 payload 的资产、在途、持仓和状态，最后检查每日明细及重试后数据库不变。

2026-09-22 已做反向验证：仅在独立测试进程内加载旧生产提交 `13558e4` 的持仓计算方法，新验收在“应有 3000 元生息本金、实际为 0”处失败。该验证未更改工作区源码或生产数据，证明验收可以拦截本次已知错误。

当前实现的完整测试为 `1060 passed in 71.84s`，编译和 Git 空白检查通过。链路测试使用独立临时 SQLite 数据库与固定行情，通过重新打开数据库验证持久化后的重试结果。

## 发布时实际使用的门槛

1. 新增完整链路回归放在 `tests/test_portfolio_lifecycle_contract.py`，由项目 `pytest -q` 自动收集。现有生产部署脚本在上传前执行全量测试并检查退出码，因此这些断言失败会阻止上传。
2. 调整资金规则前后都核对上述业务约束；涉及历史数据的变更，还须在一致的生产数据库副本上回放。预期金额必须来自明确业务规则，不能只比较两次同源计算。
3. 生产代码和数据操作分别备份。补账先预演，执行时复核数据版本与结果，保留冲正和审计，验证重试不会重复入账。
4. 上线后按只读接口验证实际资产、在途、确认状态和每日收益；HTTP 200、进程运行和文件哈希用于检查发布状态，不能代替金额核对。

目前全量测试门槛由部署脚本自动执行；生产快照回放和上线金额核对仍属于发布时执行的验证步骤，尚未全部接入自动发布程序。

## 尚待补齐的运行中检查

现有组合周期主要记录日志，不能把日志中的 `income` 数量视为本轮新入账数量：已存在的幂等收益也会被计入该数量。后续需要以交易日期和状态检查应计未计、应确认未确认，以及最近一次成功周期；异常应在产品中清楚可见。

这些运行中检查尚未因本文件而实现。涉及自动暂停某类交易、自动修正历史金额或发送通知的行为，需要单独定义条件和验收，不能把不完整的检测直接变成新的生产写入逻辑。
