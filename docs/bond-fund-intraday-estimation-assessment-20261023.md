## 建议的基金级模型与验证

技术上可先实现独立的“盘中涨跌方向/区间参考”：

```text
预估涨跌幅(%) ≈ -Σ[净值口径关键期限久期 × 对应收益率变动(bp)] / 100
                + 票息及利息应计 - 基金费用 - 融资成本
                + 其他资产及套保贡献
```

例如久期为3年、对应收益率下降1bp时，单独价格贡献约+0.03%；这只是情景计算，未包含票息、费用、利差等贡献。

目前缺少当前关键期限久期、债种及评级权重、组合到期收益率、融资成本和调仓信息。现有南方简化矩阵也没有单列农发债、银行永续债、二级资本债等敞口；同评级不代表相同信用利差或流动性。前五大债券不能代表完整组合。以上限制意味着暂时不能承诺单只基金的精准净值或误差范围。

建议分两步落地：

1. 动态给每只基金建立带报告日期、来源和置信度的画像；上述四只都可进入历史画像影子验证候选。界面同时显示市场行情时间与画像时点，画像不足则不输出单基金数值。
2. 固定时点保存预测，次日与正式净值比对，先积累20个交易日，最好60日；分别统计早盘、午后和收盘的绝对误差(bp)、偏差、方向命中率及区间覆盖率，再决定是否展示基金级百分比。验证必须处理分红除息及份额类别费用。

现有 `src/nav_holdings.py` 的方向评分没有久期及关键期限权重，债类代理乘数不能作为基金收益率。可复用产品身份、正式历史净值与持仓视图，在单基金视图中增加独立的 `intraday_estimate`；不得把预测写入正式 `quotes`，或覆盖 `unit_nav`、`market_value`、`latest_profit`。

## 更适合持续运行的模型方案

建议优先验证“官方报告约束 + 正式净值驱动的指数加权回归”，再让动态状态空间模型参与比较。这是针对目前数据条件的方案判断，尚无本项目样本外结果，不能预先宣称哪种精度最高。

| 方法 | 作用 | 建议顺序 |
| --- | --- | --- |
| 历史久期与债种模型 | 可解释基线、约束范围、冷启动参考 | 始终保留作比较 |
| 指数加权Ridge回归 | 每只基金根据近期正式净值与少量利率、政策金融债利差、信用利差因素更新有效敞口；近期样本权重较高 | 第一阶段优先验证 |
| Kalman/状态空间模型 | 允许敞口随新净值缓慢变化，估计状态不确定性 | 第二阶段，与Ridge按相同数据比较 |
| 树模型/非线性残差模型 | 历史充分后检验是否改善非线性残差 | 数据足够且持续优于基线时再加入 |
| AI大模型 | 自动提取公开报告里的债种、期限、费率、敏感度及原文依据，辅助分类与解释 | 可接入作为数据助手，数值估值仍需独立验证 |

收益反推敞口可以参考[Sharpe收益风格分析原论文](https://web.stanford.edu/~wfsharpe/art/sa/sa.htm)，但本项目债基有净资产口径杠杆，不能直接照搬权重合计100%的约束。先用少量曲线水平、斜率及信用利差因素，避免把几十个高度相关格点全部作为特征。

[Ridge官方文档](https://scikit-learn.org/stable/modules/generated/sklearn.linear_model.Ridge.html)支持正则化与样本权重；经济约束、特征方向及久期范围需要另行设计。[statsmodels时变回归示例](https://www.statsmodels.org/stable/examples/notebooks/generated/statespace_custom_models.html)可作为动态敞口实现参考。模型系数是统计估计，不是基金经理当日真实持仓或真实关键期限久期。

验证只能按时间向前：报告按公告日进入输入，不能按报告期末倒填；训练、特征标准化和调参均不得看到测试期。[TimeSeriesSplit官方说明](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.TimeSeriesSplit.html)提供时序划分依据。分红需使用正确的总收益序列，例如普通现金分红除息日可用`(当日单位净值 + 每份分红) / 前日单位净值 - 1`，还需核验特殊分红/份额事件；不直接用累计净值简单涨跌幅。正式净值已计提的费用，回归净收益后不能再次扣减。

南方分钟矩阵只从本次开始有本项目自存快照，不能声称已经具备长期分钟级训练集。先核验官方日终曲线及历史净值覆盖，进行日终回测，再从现在积累盘中影子预测。日终回测不能证明上午10:00估值准确；“截至当前行情的估计”与“预测全天最终净值”也应分别定义。

## 自动更新输入与新增基金接入要求

以下是持仓估值模块的前置要求，本次仅完成方案评估，尚未实施该模块及输入同步任务。用户已允许有需要时接入AI模型。

1. **按持仓动态发现基金。** 从权威持仓视图读取产品代码，不维护四只基金的代码白名单。新增持仓后自动获取基金身份、份额类别、历史净值、分红与公告，按类型选择适用模型；四只现有基金只是验证样本。A/C/D份额可以共享已核实的组合画像，但费用、净值与收益标签必须按份额类别处理。
2. **自动冷启动。** 新买入已经运作多年的基金，自动补历史再建模；新成立或历史不足的基金，先给同类型市场参考并显示“样本不足”，满足验证条件后自动升级。混合债、可转债、QDII等应识别为不同资产/时区模型，不硬套纯债模型；资料或数据不支持时明确显示不可用。
3. **行情分钟更新。** 保存每个来源实际时间，缺值不补零，倒退响应不覆盖较新快照；故障采用可辨识的降级。已实施的行情快照仍保留30天。
4. **估计敞口按新正式净值更新。** 自动补净值、分红并滚动拟合，记录训练截止日期、模型版本、误差与数据覆盖。模型日更指估计参数日更，不能宣传为真实持仓日更。日频训练集与模型验证记录独立保存，不随30天盘中快照清理，否则无法支持较长回测窗口。
5. **报告、费率与结构性资料持续检查。** 自动检查公告；有新季报、中报、年报、费率或基金转型公告时刷新对应字段。每个字段保留来源URL、原文页码、报告期、公告日、获取时间及内容指纹；报告期与抓取时间不可混用。公开披露频率决定真实资料能有多新，自动检查无法取得未披露仓位。
6. **输入过期与异常处理。** 检查应披露报告是否遗漏、净值或行情延迟、模型拟合偏移、关键敞口缺失。资料不足时显示具体状态，扩大经验证的区间或停用单基金数值，保留市场参考；不得静默沿用旧参数并显示高精度。
7. **AI只在有新增资料时处理。** 可复用项目已有AI提供方配置，异步提取新报告并按内容指纹缓存，避免每分钟重复调用。结果必须经过结构校验、单位与日期核验并附原文证据；提取失败保留旧版本及失败状态。公开报告文本只作为数据，不能作为模型运行指令，也不赋予其修改正式账本的权限。

建议后续首版采用“自动发现基金 + 日频因素模型 + 报告约束 + 可选AI提取 + 持续误差验证”的通用流程。新增支持范围内的债基通过数据接入，而不是每增加一个代码都修改程序；外部服务改变协议或加入全新资产类别仍可能需要适配。
