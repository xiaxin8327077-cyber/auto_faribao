## 实现方式

使用通用流程：动态发现基金 → 自动补历史净值及分红 → 发现公告并形成有证据日期的画像 → 构建固定低维债市因素 → 久期基线/指数加权Ridge → 盘中快照 → 次日用正式净值验证并更新参数。Kalman后续作为竞争模型，依据相同条件的样本外误差决定是否加入。

AI用于公开报告的字段提取、分类与解释，返回结构化字段和原文证据；不要让大模型自由生成一个涨跌数当估值结果。缺失资料应为null/未知，不能编造当前持仓、久期或置信度。报告文本不是可以执行的指令。

请按实施方案新增独立估值库`data/fund_estimation.db`，只读正式产品/持仓/交易作为发现输入，避免修改当前正式账本SCHEMA_VERSION=7。新增模块应能独立关闭、失败或迁移而不影响现有交易和定时任务。

必须从产品身份动态识别支持范围，包含持有份额大于零或存在有效待确认买入的公募基金；取消/失败买单、已清仓且无在途基金不继续高频刷新。A/C/D等份额需要分别处理净值与费率，只有证据充分时才共享组合画像。

新买入已有多年历史的基金自动回补、训练；新成立/历史不足的基金先给“同类市场参考/数据准备中”。不支持的资产类型说明原因；不能假装所有混合债、转债、QDII都适用纯债模型。

## 数据和模型正确性

- 1bp收益率变化=0.01个百分点；久期3年、收益率上行1bp，单独价格贡献是-0.03%。百分数`0.03`表示0.03%，1蛋=0.01%。
- 南方空BP是缺报价，不是0；四类收蛋区间是市场参考，不是单基金真实收益率。
- 历史日终曲线与南方盘中矩阵不是天然同口径；分来源保存并验证映射，不能拼接后宣称精度已验证。
- 净值历史回补不能只拿当前公开接口第一页100条，需验证页数/日期覆盖。分红总收益和份额事件要正确处理，分红缺失不能悄悄当0。
- 净值基准日必须与盘中BP的前收盘基准对齐；净值延迟跨多个交易日时首版降级，不能将单日行情套在更早净值上。“当日无分红已核验”与“分红数据缺失”分开处理。
- 每条输入保留来源、公告/可见时间、报告期和版本。报告在公告后才能用于训练/回测，不能倒填到报告期末。
- 模型参数由新正式净值滚动校准；它们是统计有效敞口，不等于每天获知真实持仓。
- 正式净值已反映费用，拟合净收益后不要重复扣费。净值口径久期已包含杠杆效应，勿再次乘债券仓位。
- 不把未经校准的情景范围叫概率置信区间；不使用当日收盘行情证明上午估值准确。
- 首版默认关闭`ready`质量标签；交付真实盘中验证结果和可配置质量门槛，审定前使用`experimental/reference`，不能把测试通过当作精度已验证。
- 日频训练/报告/模型/验证记录独立长期保留，不随30天盘中快照删除。

四只现有基金015736、006902、003923、400030仅为验收样本，不是白名单。研究文档中的2026-06-30中报久期代理只是历史先验；东方添益上下行敏感度不同，中心约6.36年不能当当前精准久期。

网络、PDF解析、AI、训练在后台队列中运行；GET接口只读快照，不能同步跑模型或采集。服务启动构建依赖时也不能联网。每基金任务幂等、有限重试/退避；并发发布时重读并保留较新源版本。
